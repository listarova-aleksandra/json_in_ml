Структура JSON

Два корневых элемента

Любой JSON-документ начинается с одного из двух корневых элементов: объекта или массива.

Объект — набор пар «ключ: значение» в фигурных скобках { }. Это самый распространённый вариант.

{
    "model": "RandomForest",
    "accuracy": 0.94
}

Массив — упорядоченный список значений в квадратных скобках [ ]. Используется, когда нужно передать коллекцию однотипных элементов.

[
    "age",
    "income",
    "region"
]

Правила синтаксиса

  1. Ключи всегда заключены в двойные кавычки
  2. Значения отделяются от ключей двоеточием
  3. Пары разделяются запятыми
  4. После последнего элемента запятая не ставится
  5. Строки — только в двойных кавычках (одинарные не допускаются)
  6. Нет комментариев — JSON не поддерживает // или /* */

Вложенные объекты

Значением ключа может быть другой объект. Это позволяет создавать иерархические структуры данных. В ML вложенные объекты часто используются для группировки параметров.

{
    "model": "RandomForest",
    "parameters": {
        "n_estimators": 100,
        "max_depth": 10,
        "min_samples_split": 2
    }
}

Здесь ключ "parameters" содержит вложенный объект с тремя парами. Такая структура удобна, потому что логически связанные параметры сгруппированы вместе.

Массив объектов

Массив может содержать объекты. Это один из самых распространённых паттернов в JSON — например, список экспериментов или записей датасета.

{
    "experiments": [
        {
            "name": "experiment_1",
            "model": "LogisticRegression",
            "accuracy": 0.87
        },
        {
            "name": "experiment_2",
            "model": "RandomForest",
            "accuracy": 0.94
        },
        {
            "name": "experiment_3",
            "model": "GradientBoosting",
            "accuracy": 0.96
        }
    ]
}

Массив "experiments" содержит три объекта, каждый описывает отдельный ML-эксперимент. Все объекты имеют одинаковую структуру, что делает данные предсказуемыми и удобными для обработки.

Разбор сложного примера

Рассмотрим реалистичный JSON-файл конфигурации ML-модели и разберём каждую его часть.

{
    "project": "customer_churn",
    "version": 2,
    "model": {
        "type": "GradientBoosting",
        "parameters": {
            "n_estimators": 500,
            "learning_rate": 0.05,
            "max_depth": 6
        }
    },
    "features": ["tenure", "monthly_charges", "contract_type"],
    "target": "churn",
    "trained": true,
    "notes": null
}
Ключ Тип Назначение
project Строка Название проекта
version Число Версия конфигурации
model Объект Вложенный объект с типом модели и параметрами
features Массив Список признаков для обучения
target Строка Целевая переменная
trained Boolean Обучена ли модель
notes Null Заметки (пока отсутствуют)

Частые ошибки

При написании JSON легко допустить ошибку. Вот самые распространённые:

  • Запятая после последнего элемента — {"a": 1, "b": 2,} — это невалидный JSON
  • Одинарные кавычки — {'model': 'RF'} — JSON требует только двойные
  • Комментарии — // comment — в JSON не поддерживаются
  • Ключ без кавычек — {model: "RF"} — ключ обязательно в двойных кавычках

Фан факт

JSON Schema — это отдельный стандарт, который позволяет описывать ожидаемую структуру JSON-документа и автоматически валидировать данные. В ML это используется для проверки входных данных API.
