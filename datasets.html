JSON и датасеты

Данные для ML в формате JSON

В машинном обучении данные обычно представлены в табличном формате: строки — это объекты (наблюдения), столбцы — признаки. Хотя для хранения больших датасетов чаще используется CSV, JSON незаменим при передаче данных через API, сохранении отдельных записей и описании метаданных датасета.

JSON позволяет представить каждую запись как объект с именованными полями, что делает данные самодокументируемыми — по ключам сразу видно, что означает каждое значение.

Пример: одна запись датасета

Представим датасет для предсказания оттока клиентов. Одна запись в формате JSON:

{
    "customer_id": 1042,
    "age": 34,
    "gender": "female",
    "tenure_months": 18,
    "monthly_charges": 72.5,
    "contract": "month-to-month",
    "churn": true
}

Каждый ключ — это название признака, а значение — данные конкретного клиента. Поле "churn" — целевая переменная (то, что модель будет предсказывать).

Несколько записей

Набор записей представляется как массив объектов:

[
    {
        "age": 25,
        "income": 45000,
        "city": "Moscow",
        "churn": false
    },
    {
        "age": 41,
        "income": 82000,
        "city": "Saint Petersburg",
        "churn": true
    },
    {
        "age": 29,
        "income": 55000,
        "city": "Kazan",
        "churn": false
    }
]

Табличное представление тех же данных

Те же записи в виде таблицы — привычный формат для ML-инженера:

age income city churn
25 45 000 Moscow false
41 82 000 Saint Petersburg true
29 55 000 Kazan false

JSON и таблица содержат одни и те же данные. Разница в том, что JSON — это текстовый формат для передачи данных между программами, а таблица — визуальное представление для человека.

Метаданные датасета

Помимо самих данных, в JSON удобно хранить описание датасета — метаданные. Это помогает другим разработчикам понять, с какими данными они работают.

{
    "name": "customer_churn_dataset",
    "version": "2.1",
    "num_records": 7043,
    "num_features": 19,
    "target": "churn",
    "task": "binary_classification",
    "features": [
        {"name": "age", "type": "numeric"},
        {"name": "gender", "type": "categorical"},
        {"name": "tenure_months", "type": "numeric"},
        {"name": "monthly_charges", "type": "numeric"},
        {"name": "contract", "type": "categorical"}
    ],
    "source": "Kaggle",
    "license": "CC BY 4.0"
}

JSON vs CSV для датасетов

Оба формата широко используются в ML, но у каждого свои сильные стороны:

Критерий JSON CSV
Читаемость Высокая: ключи описывают данные Средняя: нужна строка заголовков
Вложенные структуры Поддерживает Не поддерживает
Размер файла Больше (ключи повторяются) Компактнее
Использование в API Стандарт Редко
Хранение больших датасетов Не оптимально Стандартный выбор

На практике большие датасеты хранятся в CSV или Parquet, а JSON используется для передачи отдельных записей через API и хранения метаданных.

Фан факт

Формат JSON Lines (.jsonl) — это вариант JSON, где каждая строка файла является отдельным JSON-объектом. Такой формат часто используется для хранения больших датасетов, потому что позволяет читать файл построчно без загрузки в память целиком.
